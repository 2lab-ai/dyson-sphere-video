# Edit spec (v2) — trinity consensus, 2026-09-29

Why v2: v1 was a "karaoke version" — one global lyric overlay (`engine/hud.ts`) over 10 section-long screensaver
plates (avg 23 s, three over 30 s) with the same beat FX on everything. The reference (mexicat/pdoom-video) cuts on
lyric phrases (22 plates / 156.65 s = 7.12 s avg), has sub-cuts inside plates, and every plate draws the lyric
itself as part of the image. Root causes, ranked: (1) lyric ownership inverted (global subtitle layer),
(2) sections used as the edit unit, (3) one visual idiom + uniform global FX, (4) plates delegated as "backgrounds"
with no lyric/shot contract. Panel: grok-4.7 / gpt-6-astra / fable, unanimous at round 5.

## Cut list (owned by the editor: `analysis/editplan.py` → `data/edit.json`)

- Every plate ≤ 4 bars (9.323 s). No exemptions. The scene changes at least every 4 bars (implied by the cap).
- A vocal plate owns 1–2 whole lyric lines. No plate boundary inside a lyric line; a change inside a line is a shot.
- Vocal plate start = the beat at/before its first word (b ≤ t); if that beat lies inside a previous lyric line,
  the first word's exact time. Instrumental plates start on downbeats. The plate right after a vocal plate starts on
  the first downbeat after the owned lines end, or the first beat after them if that downbeat would break the cap.
- Plate count ≥ 36, no upper bound (the current edit has 41). Per-plate shots, beats and events: docs/STORYBOARD.md (generated by analysis/storyboard.py, trinity-approved 2026-09-29).
- Accent plates are set by the editor (`ACCENT` in `analysis/editplan.py` → `accent: true` in `data/edit.json`):
  currently p06-sign-neon and p36-sign-ring.
- Every vocal plate carries an `event`: the concrete on-screen event derived from what its lines say. The through-line
  motif (a point of light → orbits → shell → the point again) links plates; it never replaces a line's meaning.

## Plates and shots

- Each plate module (`app/src/scenes/<module>.ts`) draws its own lyric lines with the shared helper
  (`app/src/engine/lyric.ts`: layout, per-syllable progress, readability); position, motion, material are the plate's.
  Sung syllables highlight at their start, never ahead of the voice.
- Each module has a pure shot list (`app/src/scenes/<module>.shots.ts`) and renders from `stateAt(t)`.
  A structural transition = a change of camera framing, layout, medium or topology. Zooms, flashes, colour changes,
  word highlights and bloom don't count; nor does an id-only change.
- ≥ 60 structural transitions in the song (plate cuts + shots, simultaneous events counted once), no upper bound.
  Max gap without a transition: drop1/drop2/climax 1 bar, other vocal sections 2 bars, intro/outro 4 bars
  (`gapCap()` in `engine/shots.ts`; a gap spanning sections takes the strictest cap).
- The beat is always visible on screen. Every plate module drives a clearly visible per-beat response from
  `app/src/engine/beat.ts` (`beatPulse`, `kickPulse`, `downbeatPulse`): a scale/position snap, a luminance hit, a
  line weight, a stamp — authored by the plate in its own idiom, never a uniform global overlay.
- Hits (punch zooms, flashes, shakes) are authored per shot via the plate's post overrides. No global beat FX.

## Look

- Palette tokens only (`engine/palette.ts`): ink, ink2, bone, paper2, graphite, signal (stellar orange), ember, accent (cyan). No colour literals in
  `scenes/`. Accent on ≤ 2 plates. Bloom default 0 (shots opt in). No hue cycling.
- Bright (bone paper) plates ≥ ceil(n/4). Distinct idioms ≥ 8, never the same module on adjacent plates.
- Retired idioms (not reused, not even as helpers): synthwave grid + sun, hyperspace tunnel, split-screen glitch,
  kaleidoscope. Reusable primitives from v1 live in `app/src/engine/prim/` only: ignite ramp, swarm instancing,
  shell sphere geometry, afterglow decay, eye ring mask. Scenes never import other scenes.
- One plate (p26-popup-city) is a pop-up book spread (paper pieces hinge up; technique inspired by landfill/A.I., no code or
  drawings copied).

## Gate (`app/scripts/edit-gate.ts`, runs before any render; fail-closed)

1. Timeline: exact coverage [0, duration), rules above, every lyric line owned by exactly one plate.
2. Code paths: no global lyric HUD / lyric style / global fx in production; every vocal plate's module actually calls
   the lyric draw helper with its owned lines; every module calls a beat pulse (`engine/beat.ts`); no colour
   literals in scenes; no scene→scene or retired-idiom imports; `accent` only behind `params.accent`.
3. Shots: transitions ≥ 60 and the max-gap rules, from the pure shot lists; `stateAt` deterministic.
4. Self-test: 8 negative fixtures must FAIL, each on the check it targets (v1 10-entry timeline; one state split into
   many plates; id-only shot changes; lyric binding without a draw call; global karaoke restored; a cut inside a
   lyric line; a syllable highlighted before it is sung; a module without a beat-pulse call), and a positive control
   (the real cut list with compliant synthetic modules) must pass. Otherwise the gate itself is broken.

A green gate means the structure can't regress to v1. It is not an aesthetic approval — contact sheets are reviewed
by eye (a >15% saturated-area plate is flagged there as a warning, not a failure).
